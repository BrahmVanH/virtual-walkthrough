# Project context: virtual walkthrough

A client-side web app for virtual walkthroughs of event venues and similar
spaces. Users supply photos; a Rust crate compiled to WASM stitches them into
panoramas in the browser; the SvelteKit app presents the walkthrough. Processing
stays on the client, so don't introduce server-side image handling without
asking.

## Layout

- `src/` SvelteKit app (Svelte 5, TypeScript, Tailwind v4)
  - `src/lib/wasm-loader.ts` lazy, browser-only loader for the WASM package
  - `src/routes/` pages; `layout.css` is the Tailwind entry (`@import 'tailwindcss'`)
- `pano-stitcher/` Rust crate (edition 2024, `cdylib` + `rlib`), its own git repo
  - `src/lib.rs` AKAZE feature extraction, Hamming matching with Lowe ratio
    test and symmetric cross-check over adjacent image pairs
  - `src/homography.rs` normalized DLT + ARRSAC homography estimation
- `static/wasm/` wasm-pack output (generated by `npm run wasm`; don't hand-edit)
- `build-netlify.sh`, `netlify.toml` Netlify build (installs Rust + wasm-pack,
  builds WASM, then SvelteKit)

## Stack conventions

- **Svelte 5 runes only** (forced in `svelte.config.js`): `$props`, `$state`,
  `$derived`, `$effect`, snippets and `{@render}`. No `export let`, `$:`, or
  slots. Check the Svelte MCP docs rather than relying on memory.
- **Tailwind v4, CSS-first**: there is no `tailwind.config.*`. Theme tokens go in
  CSS via `@theme` in `layout.css`.
- **Adapter**: `@sveltejs/adapter-netlify`.
- **WASM is browser-only**: guard with `browser` from `$app/environment` or
  load inside `onMount`/`$effect`; never import it during SSR.
- **Rust/JS boundary**: exported functions use `#[wasm_bindgen]`; pass image
  data as `&[u8]`/`Uint8Array` or `ImageData`, structured results via
  `serde-wasm-bindgen`. Return `Result<_, JsError>` across the boundary instead
  of panicking; reserve `unwrap` for cases that provably can't fail.
- **Logging in WASM**: `println!` goes nowhere on `wasm32`. Use the `log` /
  `tracing` crates already in `Cargo.toml`, not `println!`.
- **Determinism**: RANSAC uses a seeded `Pcg64` to avoid `getrandom` on WASM and
  keep runs reproducible. Keep it that way unless the user decides otherwise.
- **Formatting**: tabs in Svelte/TS/config files (match the file you're in);
  `rustfmt` defaults for Rust.

## Workflow

- The user builds, tests, and deploys. See `build-and-verification.md`.
- Two separate repos: `pano-stitcher/` has its own `.git`; the workspace root
  currently has none. Don't run git write commands without being asked.
- Design skills are manual steering files (`skill-frontend-design.md`,
  `skill-minimalist-ui.md`, `skill-redesign-existing-projects.md`); use one only
  when the user pulls it in with `#`.
